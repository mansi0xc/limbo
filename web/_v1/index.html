For transactions that aren’t valid yet.

The alt mempool asks one question: is this valid against the head? Two kinds of perfectly good transactions fail it. Trellis is a node that holds them: the ones that are valid later, and the ones that are valid right after another.

The gap

The mempool only knows now.

With EIP-8141, validity is programmable. An account can say exactly when it approves a transaction. But ERC-8421 checks every transaction against the current head and nothing else, so anything whose moment hasn't come yet gets turned away.

Valid now

An ordinary transfer or swap. It passes against the head, so the standard alt mempool admits and gossips it.

ERC-8421 · admittedTrellis · not needed

Valid later

A DLC payout cheque that only works once an oracle attests. A rescue that only works once its owner goes quiet. Signed today, valid the moment a condition holds.

ERC-8421 · rejectedTrellis · PARK holds it

Valid right after

A trade that's only valid right after a market maker's quote, in the same block. Before the quote it fails. One block later the quote is stale.

ERC-8421 · rejectedTrellis · PRED pairs it

PRED Valid right after

The quote runs first, or the trade doesn’t run.

A trade names the pending quote it depends on. Its pay frame approves gas only if that quote already ran earlier in the same block, so a stale trade can't land at all and the pool never pays for one.

Under the hood

Just frames. No new opcodes.

Both rules are node policy, not a consensus change. The condition lives in a VERIFY frame, so consensus enforces it and the node only has to decide when to forward.

frame 0VERIFYexpiry_verify(deadline)

Every parked transaction expires, so nothing sits in a park area forever.

frame 1VERIFYself_verify(latch, event, tag)

The signed trigger. The account reads the latch and approves only when it holds the expected tag.

frame 2SENDERpayout(winner)

The first payout, exactly as both parties signed it.

frame 3SENDERpayout(fee)

A second payout in the same transaction. No keeper rebuilds it.

frame 0VERIFYonly_verify(trader)

The trader's own signature check. It approves execution, not payment.

frame 1VERIFYvalidateTake(#42, in, minOut)

The pool's pay frame. It approves gas only if quote #42 ran in this block and the trade fits it.

frame 2SENDERtake(#42, minOut)

The swap itself. It re-checks the quote and that frame 1 succeeded.

optionalframe 3VERIFYassertFilled()

Fails the whole transaction if the swap reverted, so the pool never pays for a failed body.

The rules

Written as a spec you can argue with.

Each rule is a node policy any ERC-8421 node can opt into. PARK-070 and the PRED topic are proposed as amendments.

PARKbuilt · tested
PARK-010The signed self_verify data declares the latch, the event and the expected tag.
PARK-020The sender is staked, so a foreign-state trigger read is allowed.
PARK-030The account is bound to an allow-listed template, and every signature is verified.
PARK-040Every parked transaction carries an expiry frame.
PARK-050Live caps per sender and per trigger. Entry P+1 is rejected.
PARK-060Index by (latch, event, tag). Promote the match and evict the losers without simulation.
PARK-070The park area may hold mutually exclusive siblings. Only the promoted one goes live.
PARK-080Optional gossip. Peers revalidate on their own. Gossip leaks timing.
PREDdraft · building
PRED-010A trade names exactly one pending quote, checked against the quote's calldata with no simulation.
PRED-020Admitted trades can't exceed the quote's size. Caps per quote and per trader, plus a minimum trade.
PRED-030One quote per maker per block. A newer sequence evicts trades bound to older ones.
PRED-040Forward the quote only with its trades, aimed at one block. Drop whatever misses it.
PRED-050Reputation for makers whose quotes don't land and traders whose trades go invalid.
PRED-060Its own gossip topic, carrying the quote's hash.
PRED-070Proposed: allow one trailing VERIFY frame that asserts the body succeeded.
The edges

What it doesn’t do.

i

It doesn't force inclusion.

PRED forces order, not inclusion. A builder can still leave the pair out.

ii

The builder still picks the quote.

Inside one block, whoever orders it decides which quote lands. Selective inclusion is still open.

iii

A revert check also stops stale fills.

What validity adds is that a stale trade can't land at all, so pool-paid gas is safe to offer.

iv

Gossip leaks timing.

Peers that see a parked transaction learn it exists. Gossip is optional for that reason.
